# 主题与背景维护

## 日常使用

导航旁的月亮／太阳按钮切换深浅主题，旁边的山景图标循环切换当前主题的三张背景。鼠标悬停可看提示；键盘 Tab 可聚焦，Enter 或空格可操作。页脚注明当前照片作者，并链接到原图页。

首次访问跟随系统深浅偏好，在未手动选择前也会响应系统主题变化。手动选择以后，以用户选择为准；同一浏览器、同一站点内的刷新与跳转均会保留。浅色和深色分别记录各自的背景。浏览器不允许本地存储时仍能切换，只是关闭或刷新后无法保证保存。

要恢复跟随系统，可在浏览器站点设置中清除本站点数据。这也会恢复默认背景。本地预览地址和线上域名分别保存偏好。

## 本地预览与构建

在 PowerShell 中执行：

```powershell
cd E:\blog
npm run dev
```

打开终端显示的网址（通常为 `http://localhost:4321`），依次检查 `/`、`/blog/`、`/about/` 和 `/blog/markdown-style-guide/`。开发服务保持运行期间可实时预览。项目约定后台启动时使用 `npm run dev -- --background`，可用 `npm run astro -- dev status` 查看状态，用 `npm run astro -- dev stop` 停止。

```powershell
npm run build
```

构建结果仍输出到 `dist`，Markdown 文章位置及路由没有改变，也没有新增页面路由。没有自动提交或推送；本地确认后再按既有 GitHub → Cloudflare Pages 流程发布。

## 添加一张背景

1. 选取许可明确、适合裁切的照片，保存作者、原图页及许可链接。
2. 用图片工具导出横屏 WebP（建议 1800 × 1200，尽量低于 220 KB）及竖屏 WebP（建议 720 × 1080，尽量低于 80 KB）。例如存到 `public/backgrounds/light-garden.webp` 和 `public/backgrounds/light-garden-mobile.webp`。
3. 打开 `src/data/backgrounds.json`，在 `light` 或 `dark` 数组末尾添加一项。注意 JSON 对象之间需要逗号，最后一项末尾不要多余逗号。

```json
{
  "id": "garden",
  "name": "花园午后",
  "file": "/backgrounds/light-garden.webp",
  "mobile": "/backgrounds/light-garden-mobile.webp",
  "position": "center",
  "photographer": "照片作者",
  "source": "https://原图页面地址"
}
```

4. `id` 在同一主题内保持唯一；已有 `id` 不变，浏览器就能继续记住用户的选择。`position` 可改为 `center top` 等以照顾拍摄主体，但建议两个版本分别裁好。
5. 更新 `public/backgrounds/SOURCES.md`，然后本地检查并运行 `npm run build`。无需改按钮或脚本；背景数量会自动读取数组长度。

## 文件分工

- `src/data/backgrounds.json`：背景列表、作者、图片路径。
- `src/components/ThemeHead.astro`：首屏主题初始化、系统主题、偏好保存、图片预加载与淡入。
- `src/components/ThemeControls.astro`：两个轻量按钮、图标与无障碍状态提示。
- `src/components/BaseHead.astro`：让所有页面在正文绘制前初始化主题。
- `src/styles/global.css`：明暗调色、照片蒙层、正文底色、排版、减少动画与打印样式。
- `src/components/Header.astro`、`Footer.astro`：统一主题导航和页脚、照片署名。
- `src/layouts/BlogPost.astro`、`src/pages/blog/index.astro`：保持结构，调整文章和列表的阅读底色及间距。
- `astro.config.mjs`：代码块的深浅配色。

照片加载失败时回退到纯色背景，正文始终有稳定底色。系统开启“减少动态效果”时取消过渡。关闭 JavaScript 时保留跟随系统的纯色主题并隐藏切换按钮。
